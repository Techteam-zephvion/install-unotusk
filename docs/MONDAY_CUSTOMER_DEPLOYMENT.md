## 4. Runbook for Monday's Customer Pilot

### Phase A: Server Provisioning
1. Run the natively compiled Flutter **Setup App** (`setup_app`) on the customer's dedicated linux server.
2. The UI will prompt the customer to specify a Server Name.
3. The app executes the deployment, pulling immutable images, seeding secure cryptographic secrets, and starting the isolated server container.
4. The Setup App will display the reachable LAN URL (e.g. `http://192.168.1.100:8000`).

### Phase B: Employee Client Provisioning
1. On a separate machine on the LAN, launch the compiled Flutter **Employee Client** (`app`).
2. Paste the LAN URL generated by the Setup App.
3. The client will establish a connection to the server.
4. Register a new user account (this will automatically assign the user to a default organization).

### Phase C: Project Setup
1. Create a new Workspace/Project in the Employee Client.
2. Select **Connect Repository**.
3. Point to the customer's Git repository. (Ensure SSH keys / tokens are supplied if private).
4. Monitor the Ingestion status. The UI will show when it's queued, cloning, parsing, and completed.

### Phase D: Unotusk AI Experience
1. Navigate to the **Discoveries** tab to view architectural risks discovered in the repository.
2. Navigate to the **Ask** tab and ask a codebase question (e.g. "Where is the authentication service defined?").
3. Unotusk will synthesize a context-aware response, providing precise file and line citations grounded strictly in the customer's code.
