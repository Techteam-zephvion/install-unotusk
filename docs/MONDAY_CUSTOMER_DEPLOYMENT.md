# Monday Customer Deployment Readiness Report & Operational Runbook

## 1. Objective
A P0 validation and documentation of the UNOTUSK MVP release to guarantee a zero-friction server installation and end-to-end Employee Client experience for Monday's customer trial.

## 2. Release Truth and Readiness Status
**Status:** **READY FOR DEPLOYMENT (PASS)**

The deployment architecture successfully meets all MVP architectural mandates:
- Replaced developer source mounts with **immutable `unotusk-api` and `unotusk-worker` images** fetched from a registry (`ghcr.io`).
- Verified complete network isolation of PostgreSQL and Redis. They are internal to the Docker network; only the FastAPI server is exposed to the LAN.
- Complete data segregation achieved: Each deployment spins up a dedicated `docker-compose` instance inside `~/.unotusk/servers/<server_name>`, avoiding collisions entirely.

## 4. Runbook for Monday's Customer Pilot

### Phase A: Server Provisioning
1. Download `unotusk-server-linux-x64.tar.gz` from the GitHub Release.
2. Extract and run `bundle/setup_app` on the customer's dedicated linux server.
3. The UI will prompt the customer to specify a Server Name.
4. The app executes the deployment, pulling immutable images, seeding secure cryptographic secrets, and starting the isolated server container.
5. The Setup App will display the reachable LAN URL (e.g. `http://192.168.1.100:8000`).

### Phase B: Server Manager - Connect Repository
1. On the Server Manager screen inside the Setup App, locate the running Server card.
2. Click **Manage Repos**. This opens the Repository Provisioning screen.
3. Click **Connect Repository**.
4. Enter the internal Project Name, Repository URL, and (if private) a GitHub Token.
5. The Server Manager securely injects the token into the API, and triggers the repository ingestion.

### Phase C: Employee Client
1. On a separate machine on the LAN, download the appropriate `unotusk-employee` binary.
2. Launch the Employee Client and paste the LAN URL generated by the Setup App.
3. The client will establish a connection to the server.
4. Register a new user account and login.

### Phase D: Unotusk AI Experience
1. Open the Project provisioned by the Server Manager.
2. Navigate to the **Discoveries** tab to view architectural risks discovered in the repository.
3. Navigate to the **Ask** tab and ask a codebase question (e.g. "Where is the authentication service defined?").
4. Unotusk will synthesize a context-aware response, providing precise file and line citations grounded strictly in the customer's code.

## 5. Security & Credential Handling
**Credential Security (PASS):** GitHub tokens entered through the Server Manager are immediately encrypted using AES-128 via Fernet encryption before being stored in PostgreSQL. The symmetric key (`AUTH_SECRET`) is uniquely generated per server installation and sits securely in the Docker environment context. The Employee Client does not handle, store, or receive raw Git credentials, strictly enforcing the credential boundary.
